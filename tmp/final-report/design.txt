Agile Sprint Summaries 
 
Persona and User Stories 
Persona 1: Citizen 
The primary user of the system who applies for NICs and Passports, uploads required 
documents, books biometric appointments, and tracks application progress. Citizens can also 
request renewals, replacements, and support services. 
• As a Citizen, I want to  register and log into the system so that I can securely  access 
identity services online. 
• As a Citizen, I want to apply for a new NIC or passport so that I do not have to submit a 
paper application in person.  
• As a Citizen, I want to upload supporting documents so that officers can verify my 
application remotely. 
• As a Citizen, I want to track the real-time status of my application so that I know how it 
is progressing. 
 
Persona 2: NIC Application Officer 
Responsible for reviewing and verifying NIC applications submitted by citizens. The officer 
validates documents, verifies applicant information, and approves or rejects NIC - related 
requests. 
• As a NIC Application Officer, I want to review submitted NIC applications so that I can 
check applicant information for accuracy. 
• As an NIC Application Officer, I want to verify uploaded supporting documents so that 
fraudulent or incomplete applications are identified. 
• As an NIC Application Officer, I want to approve valid NIC applications so that citizens 
can proceed to document issuance. 
• As an NIC Application Officer, I want to reject invalid applications with a recorded 
reason so that citizens know what needs correcting. 
 
Persona 3: Passport Verification Officer 
Responsible for processing and verifying Passport applications and supporting documents. The 
officer reviews applications and makes approval or rejection decisions based on verification 
results.

Ethical Considerations 
Since LankaID handles sensitive information related to NIC and passport applications, ethical 
issues must be considered carefully. The system stores personal details, supporting documents, 
appointment information, and application decisions. If this information is misused or accessed by 
the wrong person, it could seriously affect a citizen. The following concerns were considered 
when designing the system. 
 
 
Data Privacy 
Citizens provide sensitive information such as their NIC or passport details, contact information, 
addresses, and supporting documents. Collecting this information is necessary for processing an 
application, but it also creates a privacy risk. 
To reduce this risk, LankaID collects only the information needed to complete the identity-
issuance process. Personal information and uploaded documents are available only to authorized 
users. For example, NIC officers handle NIC applications, while passport officers handle 
passport applications. 
The current system does not store raw fingerprint or facial images. It records only whether 
biometric collection has been completed. The payment module also stores the payment reference, 
amount, status, and date instead of saving complete card details. During testing and 
demonstrations, the team should use fictional information rather than real citizen records. In a 
real deployment, the database, uploaded documents, and backups should also be encrypted. 
 
 
User Consent and Transparency  
Citizens should know why their information is being collected and how it will be used. They 
should not be expected to provide personal information without a clear explanation. 
LankaID requires citizens to accept a declaration before submitting an application. This confirms 
that the information they have provided is true and accurate. However, the system should also 
display a separate privacy notice explaining what information is collected, why it is required, 
which officers can access it, and how long it will be kept. 
Citizens can track their application status and receive notifications when an application is 
approved, rejected, or returned for correction. When an application cannot proceed, the officer

Security and Confidentiality 
Because LankaID contains identity-related information, unauthorized access could lead to 
identity theft, fraud, or improper approval of applications. 
The system uses password hashing so that user passwords are not stored as readable text. OTP 
verification is used during important registration and identity-verification activities. LankaID 
also uses role-based access control. Citizens, NIC officers, passport officers, Citizen Service 
Representatives, directors, and system administrators have different levels of access. 
Important decisions are recorded with the officer’s ID and the date and time of the action. This 
creates an audit trail and makes officers accountable for their decisions. For an actual 
government deployment, the system should also use HTTPS, encrypted document storage, login-
attempt limits, secure backups, regular security updates, and a proper procedure for responding 
to data breaches. 
 
Accessibility and Digital Inclusion 
Not every citizen has the same level of computer knowledge, internet access, or ability to use an 
online system. Some citizens may also have visual, physical, or other disabilities. Since an NIC 
or passport is an essential document, these citizens should not be excluded from the service. 
The LankaID interface uses readable text, clear labels, visible error messages, suitable colour 
contrast, and responsive layouts that can work on different screen sizes. Important images and 
controls also include accessibility descriptions where possible. 
Citizens who cannot complete the online process independently can use the walk-in appointment 
service and receive assistance from a Citizen Service Representative. In the future, the system 
should also provide Sinhala and Tamil language options, full keyboard navigation, screen-reader 
support, adjustable text sizes, and pages that work properly with slow internet connections.

Data Retention and User Control 
Keeping personal information for an unlimited period creates an unnecessary privacy risk. At the 
same time, some application and issuance records may need to be preserved for accountability and 
to prevent fraud. 
LankaID should therefore keep information only for a clearly defined period. When a citizen 
account is removed, unnecessary contact information should be deleted or replaced with non -
identifying values. However, important application and issuance records may need  to remain in 
the system with restricted access. 
Citizens should be allowed to report incorrect information through the support and complaint -
management process. Before the system is used in a real environment, a data -retention policy 
should explain what information is kept, why it is kept, who can acces s it, and when it will be 
securely deleted. 
Fairness and Accountability 
All citizens should be treated equally during the application and verification process. Decisions 
should not be influenced by personal characteristics, social background, or an officer’s opinion. 
LankaID applies the same verification requirements to all applicants, while final approvals and 
rejections remain under the control of authorized human officers. The system does not use AI to 
make final decisions about a citizen’s eligibility. Officers must record reasons for rejections and 
correction requests, and citizens can use the complaint or support process if they believe that a 
decision is incorrect. Recording officer actions also allows unfair or suspicious decisions to be 
reviewed.
